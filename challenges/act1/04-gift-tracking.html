Gift-Tracking Port Mystery

Act 1, Challenge 4 | 📍 South of Modern Scandinavian Condo | Difficulty: ❄️

The neighborhood's Santa tracker has gone missing. The original port 8080 is gone. The tinkerer is counting on you to find where the mischievous gnomes hid the tracker using nothing but a single command and your wits. Can you locate the port before the big night?

Challenge Overview

The neighborhood's Santa tracker was originally running on port 8080, but after gnome sabotage, it's been moved to an unknown port. Your task is to locate that port and verify it's running.

Discover Listening Ports with ss

The ss command (socket statistics) is your modern replacement for the older netstat tool. It provides detailed information about all network sockets on the system, including which processes are listening on which ports.

Bash
tinkerer @ Santa Tracker ~ $ ss -tlnp
State         Recv-Q        Send-Q               Local Address:Port                  Peer Address:Port        Process        
LISTEN        0             5                          0.0.0.0:12321                      0.0.0.0:*
Flag breakdown:
  • -t – Show TCP sockets only
  • -l – Show only LISTENING sockets (not connected ones)
  • -n – Display numeric addresses/ports (faster, no DNS lookups)
  • -p – Show the process name and PID using each socket

The santa_tracker process is listening on port 12321!

Connect to the Service Using curl

Since there's no graphical browser available in this terminal environment, curl is the perfect tool for the job.

Bash
tinkerer @ Santa Tracker ~ $ curl 0.0.0.0:12321
{
  "status": "success",
  "message": "Ho Ho Ho! Santa Tracker Successfully Connected! 🎄",
 ...
  • curl – Makes HTTP requests from the command line
  • 0.0.0.0 – Localhost address (you can also use 127.0.0.1 or just localhost)
  • :12321 – The port we discovered in Step 1

Alternate Solution: Using Telnet

There's a README.txt file in the home directory that mentions telnet as an alternative way to connect. While curl is the modern HTTP client, telnet is a classic alternative that works in restricted environments. Telnet establishes a raw TCP connection to any port, allowing you to manually interact with services. This is handy when curl isn't available or you need more control.

When we use telnet the output by default shows the HTTP response headers at the top. To see the headers in curl, add the -i switch.

Bash
tinkerer @ Santa Tracker ~ $ telnet 0.0.0.0 12321
Trying 0.0.0.0...
Connected to 0.0.0.0.
Escape character is '^]'.
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 1193
Connection: close

{
  "status": "success",
...
