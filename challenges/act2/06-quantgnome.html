Quantgnome Leap

Act 2, Challenge 6 | 📍 Grand Hotel Lobby | Difficulty: ❄️❄️

Quantum computing is coming for our keys, but are we ready to leap? This challenge takes us on a journey from vulnerable RSA to the cutting edge of hybrid post-quantum cryptography, proving that the future of security is already here...if you know where to look.

Challenge Overview

Quantgnome Leap explores the transition from classical to Post-Quantum Cryptography (PQC) within an SSH environment. Players must navigate a chain of users, each secured by progressively stronger cryptographic algorithms (from RSA to Ed25519 to Hybrid ML-DSA), utilizing the Open Quantum Safe (OQS) framework to understand how modern protocols are evolving to resist quantum threats."

Side Note: What about the Quantgnome in the box animation?

The gnome vanishing and reappearing inside a box is a direct reference to the Schrödinger's Cat paradox. In quantum mechanics, a system can exist in a "Superposition" of states (e.g., the gnome is both there and not there) until it is observed. This isn't just flavor text. It represents the fundamental danger to our cryptography. Unlike classical bits (0 or 1), Qubits utilize this superposition to perform vast calculations simultaneously. This computational parallelism is what allows algorithms like Shor's Algorithm to factor large primes exponentially faster than classical computers, necessitating the shift to Post-Quantum Cryptography that this challenge explores.

Background Info: The Quantum Threat & Defining "Post-Quantum"

The Threat: Why RSA is Doomed

Classical encryption (like RSA and Elliptic Curve) forms the backbone of the internet. Its security relies on specific mathematical problems—like factoring massive prime numbers—that are incredibly difficult for classical computers to solve.

  • Classical Computers: Operate on bits (0s and 1s). Factoring a 2048-bit key would take a standard supercomputer billions of years.
  • Quantum Computers: Operate on Qubits, allowing for superposition. They leverage Shor's Algorithm, a method developed by Peter Shor in 1994 that efficiently finds the prime factors of large integers. While a classical computer might take billions of years to factor an RSA key, a sufficiently powerful quantum computer using Shor's algorithm could do it in minutes, rendering current SSH, TLS, and banking security obsolete.

What does "Post-Quantum Cryptography" (PQC) actually mean?

The term "Post-Quantum" refers to the era after quantum computers become powerful enough to break current encryption. Therefore, Post-Quantum Cryptography does not mean using quantum computers to encrypt data.

Instead, PQC refers to new cryptographic algorithms designed to run on today's classical computers but based on different branches of mathematics (like Lattice theory or Multivariate equations) that are believed to be immune to quantum attacks.

Background Info: What is Open Quantum Safe?

The Project

This challenge is built entirely on the Open Quantum Safe (OQS) project, an initiative managed by the Linux Foundation. Their goal is to support the transition to quantum-resistant cryptography by developing and prototyping these new algorithms.

Key Components

  • liboqs: An open-source C library that contains implementations of the NIST-selected PQC algorithms (like Kyber, Dilithium/ML-DSA, Falcon, and SPHINCS+).
  • OQS-OpenSSH: A fork of the standard OpenSSH client and server. This is the software running on the challenge server (pqc-server.com).

Relevance to the Challenge

This explains why the SSH client behaved uniquely. The OQS-patched client is programmed to recognize and auto-load experimental key types (like id_mayo2) that a standard SSH client would ignore. It also enables "Hybrid" keys—a mechanism that combines a classical key (like ECDSA) with a PQC key to ensure security even if the new PQC algorithm turns out to have a flaw.

Finding and Using the First Key

We begin our journey in the terminal as the user qgnome. Following the hint about hidden directories, we find the .ssh directory with a standard RSA key pair (id_rsa and id_rsa.pub).

Bash
qgnome@quantgnome_leap:~$ ls -l ~/.ssh/
 -rw-r--r--    1 qgnome   qgnome        560 Oct 29 00:29 id_rsa.pub
-rw-------    1 qgnome   qgnome       2590 Oct 29 00:29 id_rsa

The permissions on id_rsa are 600 (-rw-------), meaning only the owner (qgnome) can read it. This is the classic setup for an identity key.

Background Info: Anatomy of an SSH Key Pair

1. Asymmetric Cryptography (The Lock and Key)

SSH relies on asymmetric encryption, which uses two mathematically linked keys:

  • The Public Key (id_rsa.pub): This acts like a padlock. You can give it to anyone (or place it on a server). It encrypts data or verifies signatures.
  • The Private Key (id_rsa): This is the physical key that opens the padlock. It must be kept secret. It is used to decrypt data or sign authentication challenges.

2. Why permissions 600?

I noted the permissions were set to 600 (-rw-------). This is a critical security requirement enforced by the OpenSSH client.

Since Linux is a multi-user system, if a private key were readable by "Group" or "World" (e.g., 644), another user on the system could copy it and impersonate the owner. If OpenSSH detects permissions are too open, it will essentially say "This key is unsafe" and refuse to use it.

3. The Math (The Vulnerability)

This specific key is RSA. It is generated by multiplying two massive prime numbers together. Its security relies on the fact that while multiplying is easy, factoring the result back into primes is computationally infeasible for classical computers.

This is exactly where the Quantum Threat lies: Shor's Algorithm turns that "infeasible" factoring problem into an easy one.

Following the hint regarding SSH key comments, I inspected the public key and found the comment gnome1. Usually, when generating a key, the comment defaults to user@hostname. The explicit label strongly suggests that this private key allows authentication as the user gnome1.

Bash
qgnome@quantgnome_leap:~$ cat ~/.ssh/id_rsa.pub
ssh-rsa AAAAB...[snip]...GkE07pWU= gnome1

I attempted to SSH into the localhost as the gnome1 user. Since the key id_rsa is in the default .ssh path, the SSH client automatically attempts to use it for authentication.

Repeating the Process

From here, the challenge became a lesson in cryptographic evolution. Each user's .ssh directory contained a private key allowing movement to the next user. I followed the chain, analyzing the key types at every "Leap."

Leap Path Key Algorithm Classification Analysis & Security Note

gnome1 → gnome2 Ed25519

You made the QuantGnome Leap! Your final stop.

You authenticated with another hybrid post-quantum key. What is different about this key? It uses the NIST

- sphincssha2256fsimple: SLH-DSA (SPHINCS+) using SHA2 256 and fast signature generation (hence

- mayo5: MAYO-5 is the highest of the four MAYO security levels

Understanding the NIST Column (Security Levels)

NIST column in the pqc-keygen output refers to the five specific security categories defined by NIST during the PQC standardization process. These levels map the difficulty of breaking the new algorithms to well-known symmetric encryption standards:

  • Level 1: Equivalent to AES-128 (Fastest, Smallest Keys)
  • Level 3: Equivalent to AES-192 (Balanced)
  • Level 5: Equivalent to AES-256 (Maximum Security, Larger Keys)

Observation: Note that rsa-2048 and ed25519 are marked as 0. In the context of a quantum adversary, they provide zero bits of security.

Official Hints

  • When you give a present, you often put a label on it to let someone know that the present is for them. Sometimes you even say who the present is from. The label is always put on the outside of the present so the public knows the present is for a specific person. SSH keys have something similar called a comment. SSH keys sometimes have a comment that can help determine who and where the key can be used.
  • If you want to create SSH keys, you would use the ssh-keygen tool. We have a special tool that generates post-quantum cryptographic keys. The suffix is the same as ssh-keygen. It is only the first three letters that change.
  • User keys are like presents. The keys are kept in a hidden location until they need to be used. Hidden files in Linux always start with a dot. Since everything in Linux is a file, directories that start with a dot are also...hidden!
  • Process information is very useful to determine where an application configuration file is located. I bet there is a secret located in that application directory, you just need the right user to read it!
